## 协作与维护规则

计划按执行顺序写，明确下一步和必要前置条件。每个独立功能单列同级任务，简单任务只写两三条必要步骤和完成标准；普通步骤用缩进子项，需要单独跟踪时才使用子 TODO。

未完成统一使用 `- [ ] TODO`，开始处理后不改状态；验收通过才改为 `- [x] DONE`。完成标准写用户能看到的结果，未执行或未通过的检查不得勾选。

暂缓事项移入[可选功能](可选功能/README.md)并保留原因；取消事项说明原因后归档，不记为完成。每次推进一个小任务，完成后将任务内容和实际验收证据移入[归档](归档/README.md)，此处只保留简短索引。

需求、设计、API 各司其职。正式资料持续维护在原目录，归档只引用；接口交付包括同名 OpenAPI 和中文说明。文档、原型、前端、后端、真实联调分别记录，任何单一阶段通过都不代表整项功能完成。

复杂任务才在[项目参考](项目参考/README.md)补充详细方案；简单任务不额外建文档。关键约定和验证结果随任务记录，避免在 TODO 堆积技术细节。
