# 账号与后端部署

## 服务和数据

后端为 Node.js 24 内置 HTTP + SQLite，无独立数据库服务依赖。`pnpm build` 会编译前后端共用的训练校验规则；后端 `dist` 必须和 `server.cjs` 一起部署。前端产物位于 `apps/web/dist`，Node 同时提供静态文件和 `/fitness-tracker/api/*`。

默认数据库为 `apps/api/data/fitness.sqlite`，包含账号、哈希密码、会话哈希及训练 JSON。WAL 模式及条件更新保障写入与版本一致性。每用户最多 10000 条历史，单次请求最多 5 MB。单机单实例使用；暂不做多实例横向扩容。

| 环境变量 | 默认 / 要求 |
| --- | --- |
| PORT | 3001 |
| HOST | 127.0.0.1，容器中设 0.0.0.0 |
| DATABASE_PATH | apps/api/data/fitness.sqlite；线上必须指向持久卷绝对路径 |
| NODE_ENV | 线上设 production |
| APP_ORIGIN | 线上必填 HTTPS 来源，例如 https://bianfu.site，不含尾部斜杠或路径；开发默认按请求 Host 校验 |

开发：`pnpm install && pnpm dev`；构建服务：`pnpm build && pnpm start`。环境变量由进程管理器或系统注入，代码不会自动读取 `.env`。

## 线上接入

目前已有 CloudBase 静态站点，不具备本实现所需的常驻进程和持久化数据库配置。本轮未发布、未修改域名、未新增云资源。需选择有持久磁盘的 Node 主机/容器后再上线。不能将 SQLite 放在临时、发布时重建或无持久化的函数文件系统。

若沿用 `https://bianfu.site/fitness-tracker/`，网关需要把整个 `/fitness-tracker/` 子路径转发到 Node 服务，保留原博客路由。示例 Nginx 片段（在现有 HTTPS server 内配置）：

```nginx
location = /fitness-tracker { return 302 /fitness-tracker/; }
location /fitness-tracker/ {
    client_max_body_size 5m;
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

生产服务启用 Secure、HttpOnly、SameSite=Strict Cookie；会话 30 天到期，退出删除服务器会话。写请求校验 Origin，数据请求额外校验当前账号标识，避免其他标签页切换账号后误写。每个直接连接 IP 的认证尝试限制为 15 分钟 30 次，代理后可能所有用户共用配额；当前不信任客户端 X-Forwarded-For，上线用户量增长时需在可信网关实现限流及代理 IP 配置。

## 备份和恢复

用户端已移除导入导出、恢复和旧数据迁移入口。自动备份尚未配置，需在部署时设置运维任务并验证恢复。数据库是全站备份，必须限制文件权限；备份前停止服务，再复制 SQLite 文件及存在的 `-wal`、`-shm` 文件，或使用 SQLite 在线备份工具生成一致性副本。不要仅复制运行中的主数据库文件。恢复时停止服务再替换完整数据库，并验证账号和历史。

## 上线验收
