## 发布方式

使用本机 CloudBase CLI，通过用户授权的腾讯云账号部署。上传目录仅为 `apps/web/dist`，不上传源代码、依赖缓存或本地训练数据。

```sh
pnpm deploy:cloudbase
```

此命令先重新构建，再调用 CloudBase 的静态应用部署，保留应用版本管理。需事先安装 CloudBase CLI，登录失效时按 CLI 提示完成官方网页授权。已有同名应用时确认是本项目后再更新，不修改其他应用。

底层发布命令：

```sh
cd apps/web/dist
cloudbase app deploy fitness-tracker --env-id bat-d7gfpd0l3343e0e30 --framework static --output-dir . --deploy-path /fitness-tracker
```

Vite 的 `base: './'` 让静态资源使用相对路径，适用于应用子路径及独立应用域名。站点没有 URL 级客户端路由，不需要增加服务器 API 或全局重写规则。

CloudBase CLI 3.8.1 的静态上传分支会相对进程工作目录解析 `outputDir`，不能仅依赖 `--cwd` 切换上传范围。因此先实际进入 `apps/web/dist`，或使用绝对产物路径；上传前确认只有 `index.html` 和 `assets` 资源。

## 验证与数据边界

发布后检查部署状态、入口 HTML、JS 和 CSS 的 HTTP 响应，并比对线上文件与本地产物。实际版本、地址及检查结果记入部署归档。

线上域名与 localhost 属于不同数据空间。原本在本机开发页面记录的数据不会自动出现在网站上，可在原页面导出备份，再到线上页面导入。请固定使用同一个线上地址；不同域名不会共享 IndexedDB。

当前是公开可访问的静态应用，但个人训练记录不上传腾讯云，仍只存在访问者自己的浏览器中。

同一域名的不同路径共享浏览器的存储来源。当前训练使用独立的 `fitness-tracker` 数据库名称；路径不是独立的安全隔离边界。腾讯云独立域名与 `bianfu.site` 是不同来源，已有记录需要导出 / 导入迁移。
