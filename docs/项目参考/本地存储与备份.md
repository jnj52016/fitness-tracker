# 本地存储与备份

> 2026-10-23 更新：本文保留上一阶段记录。当前改用用户名密码账号与后端存储，见[当前 TODO](../todo.md)。旧静态发布方式不适用于新版本。

## 数据归属

数据库名称 `fitness-tracker`，数据库版本 `1`，对象仓库 `training`，键 `state`。一份状态包括格式版本、递增修订号、计划选择、当前分化、四组动作配置、本轮组数、开始时间、历史快照。

网址的协议、域名、端口共同决定数据空间。同一局域网不同手机仍不共享数据库。不要在不同地址间切换后误判数据丢失。

## 函数与数据流

| 位置 / 函数 | 输入 | 过程 | 输出 |
| --- | --- | --- | --- |
| `apps/web/src/data/storage.ts` / `loadData` | 当前浏览器数据库 | 读取状态并检查格式 | 已保存状态或首次空状态 |
| `apps/web/src/data/model.ts` / `countSet` | 状态、动作、加减一组 | 检查当前动作，限制在 0 与目标之间 | 修改后的本轮组数 |
| 同文件 / `finishSession` | 状态、结束时间 | 记录当前真实组数快照，轮换分化 | 增加历史后的状态 |
| `storage.ts` / `saveData` | 新状态、旧修订号 | 同一事务中比对修订号，再整体写入 | 成功保存的新修订状态；冲突或写入失败则报错 |
| `model.ts` / `createBackup`、`parseBackup` | 状态或 JSON 文本 | 导出带版本标记的数据；导入检查结构和值 | JSON 文件内容或已校验状态 |

页面操作线：读取数据库 → 在状态副本上修改组数或结束训练 → 事务保存 → 成功后展示新状态。结束训练产生的快照供历史页面与统计读取，后续配置变化不修改快照。

恢复线：用户选择文件 → 校验格式 → 展示替换摘要 → 用户确认 → 使用同一保存事务替换 → 页面显示恢复结果。取消和校验失败不会触发写入。

测试线使用 fake-indexeddb 和模拟 DOM，在独立测试进程运行，不连接用户浏览器数据。

## 备份格式

顶层字段为 `app: fitness-tracker`、`formatVersion: 1`、`exportedAt`、`data`。数据格式版本与数据库修订号是不同概念；恢复时沿用目标数据库当前修订号递增，不拿备份旧修订号覆盖。

导入文件限制 5 MB、最多 10000 条历史。动作 ID 必须属于当前计划，不能重复；目标为 1–20 的整数，完成数为 0 到目标的整数。未来修改数据结构应实现显式迁移，不丢弃未知版本数据。

## 已知边界

当前存储状态整体读写，适合个人使用；暂未实现服务器同步、自动上传备份或 Service Worker 离线站点缓存。历史时间以设备时钟为准。生产时固定一个 HTTPS 网址，可避免开发端口或 IP 变化带来的数据空间变化。

原型 `output/fitness-plan.html` 的 `fitness-html-prototype-v1` localStorage 键不自动导入。不同端口的数据无法被另一个网址直接读取。
